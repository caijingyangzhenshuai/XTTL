## 目标

在大语言处理模块（kzzk_llm）的模型交互推理时，在输出顶部显示当前执行的功能/模型名称，风格对齐 CANN 小模型推理（如 `mobilenetv1图像分类推理`）。实现 Python + C++ 两套命令行接口。

### 期望输出（用户示例）
```
python kzzk_llm.py --listModels
模型列表显示 Python版
可用模型:
   1. DeepSeek-14B

python kzzk_llm.py --modelfile DeepSeek-14B --prompt hello
DeepSeek-14B模型交互 Python版
<回复内容>
```

## 改动内容

### 1. Python 端：`mindie/python/kzzk_llm.py`
- `--listModels` 分支（当前第 33 行起）：在打印 `可用模型:` 之前，先输出一行头部 `模型列表显示 Python版`。
- 模型交互分支（当前第 62-64 行）：在打印回复之前，先输出 `{modelfile}模型交互 Python版`（如 `DeepSeek-14B模型交互 Python版`），再打印 `reply`。
- 保持 `list_models()` / `kzzk_llm()` 逻辑不变，向后兼容任意模型名（保留通用回退）。

### 2. C++ 端：`mindie/cpp/src/main.cpp`
- `--listModels` 分支（当前第 94 行附近）：在输出 `Available Models` 之前添加一行 `模型列表显示 C++版`。
- 模型交互：在输出 `Using model: ...` / `Generating response...` 附近添加一行 `{modelName}模型交互 C++版`（如 `DeepSeek-14B模型交互 C++版`），随后打印回复。
- 仅添加显示头部，不改动 HTTP 请求/结果解析逻辑，保留对任意模型名和 http:// URL 的支持。

## 说明
- 不新增 per-model 类，不改动 `client.py` / `kzzk_llm.cpp` 的通信逻辑，仅增强命令行输出的可读性与功能标识，与用户澄清的意图一致。
- 三个模型（DeepSeek-14B / Qwen3-14B / Qwen2.5-14B）交互时头部统一为 `{模型名}模型交互`，实际模型名由 `--modelfile` 传入（如服务器上名为 Qwen3-14B 时显示 `Qwen3-14B模型交互`）。
