## 1. 引言

### 1.1 编写目的

本文档是合同验收的技术依据，明确了智能加速卡协同推理工具的软件需求规格，定义了产品功能性能要求、产品清单、维护和技术责任等方面的内容，是软件采购、开发、测试和验收的基础和依据。

### 1.2 产品概述

智能加速卡协同推理工具是专为优化多块智能加速卡协同工作而设计的系统级软件平台，主要用于在人工智能推理场景中高效调度多块加速卡的计算资源，实现模型推理任务的并行处理与负载均衡。通过打破单卡性能瓶颈，提升整体推理效率与系统吞吐量。

产品基于 **华为昇腾智能加速卡（Ascend NPU）**，以 CANN（Compute Architecture for Neural Networks）和 MindIE（MindSpore Inference Engine）为底层技术支撑，提供计算机视觉（CV）与大语言模型（LLM）两类推理能力，并通过 Python 与 C++ 双语言 API 供上层应用调用。

### 1.3 软件组成

本软件可分解为以下两个核心模块：

| 模块编号 | 模块名称 | 描述 |
|---------|---------|------|
| MOD-01 | 国产智能计算加速卡协同推理接口 | 基于国产智能计算加速卡提供底层协同推理接口，提供统一、标准化的 API 调用机制，屏蔽多卡设备差异、通信瓶颈和任务分配效率低的问题 |
| MOD-02 | 协同推理开发框架 | 提供统一的协同推理执行流程管理机制，包括模型加载、任务划分、调度分发、结果聚合等关键能力，内置模型适配器、容错机制与性能监控模块 |

### 3.2 功能需求详细说明

#### 3.2.1 国产处理器/加速卡协同推理开发支持（FUN-01）✅

本软件基于国产华为昇腾 NPU 构建，支持在国产处理器（如鲲鹏 aarch64）与国产智能加速卡上进行协同推理软件的开发。上层应用通过本软件提供的 Python/C++ 接口调用 NPU 推理能力。

#### 3.2.2 协同推理接口（FUN-02）✅

国产智能计算加速卡协同推理接口是模块 MOD-01 的核心产出，提供统一、标准化的 API 调用机制：

- **C++ 接口**：`kzzk_cv::kzzk_cv(const std::string& modelfile, const std::string& imagefile)`，返回 `InferenceResult` 结构体
- **Python 接口**：`kzzk_cv(modelfile, imagefile)`，返回推理结果字典
- 通过底层驱动的抽象和统一封装，屏蔽加速卡接口和性能特性的不一致性

#### 3.2.3 协同推理开发框架（FUN-03）✅

协同推理开发框架是模块 MOD-02 的核心产出，提供统一的推理执行流程管理机制：

| 框架能力 | 描述 | 实现状态 |
|---------|------|---------|
| 模型加载 | 自动解析 `.om` 离线模型文件，初始化 ACL/DVPP 资源 | ✅ 已实现 |
| 任务划分 | 根据模型类型（检测/分类/分割）自动分配后处理逻辑 | ✅ 已实现 |
| 调度分发 | 工厂模式按文件名关键字自动匹配并创建推理实例 | ✅ 已实现 |
| 结果聚合 | 推理结果封装为标准 `InferenceResult` 结构体返回 | ✅ 已实现 |
| 模型适配器 | 自动适配不同模型的输入规格（分辨率/数据类型/预处理） | ✅ 已实现 |
| 容错机制 | 文件预检查、错误诊断、静默模式、异常捕获 | ✅ 已实现 |
| 性能监控 | 推理耗时统计（毫秒级） | ✅ 已实现 |
| 负载均衡 | 多卡任务调度与资源动态分配 | ❌ 待实现 |

#### 3.2.4 多精度推理支持（FUN-04）⚠️

系统需支持 float32、float16 和 int8 等多种推理精度：

| 精度 | 支持状态 | 说明 |
|------|---------|------|
| float32 (FP32) | ✅ 已实现 | ResNet50 支持 FP32/uint8 输入；推理结果置信度为 float 类型 |
| int8 | ✅ 已实现 | DeepLabV3+ 支持 int8 (RGB) 输入 |
| float16 (FP16) | ⚠️ 待补充 | 模型层面可在 ATC 转换时指定 FP16 输出；当前代码未显式管理 FP16 推理流程 |

> 注：推理精度的实际选择由 `.om` 模型文件在 ATC 转换时决定，软件层通过声明匹配的数据类型（FP32/uint8/int8）适配不同精度模型。

#### 3.2.5 加速卡温度/功耗实时查看（FUN-05）❌

系统需提供实时查看昇腾 NPU 温度与功耗的能力：

| 需求项 | 要求 | 实现状态 |
|-------|------|---------|
| 温度查看 | 通过 `npu-smi info` 或 ACL API 获取 NPU 温度 | ❌ 待实现 |
| 功耗查看 | 通过 `npu-smi info` 或 ACL API 获取 NPU 功耗 | ❌ 待实现 |
| 集成方式 | 建议集成 `kzzk_monitor()` API 或 CLI 子命令 | ❌ 待实现 |

#### 3.2.6 推理结果导出为文件（FUN-06）❌

系统需支持将推理结果导出为持久化文件：

| 需求项 | 要求 | 实现状态 |
|-------|------|---------|
| JSON 导出 | 将推理结果序列化为 JSON 文件 | ❌ 待实现 |
| 图像导出 | 将分割图/标注检测框图像保存为本地文件 | ❌ 待实现 |
| 文本导出 | 将 LLM 推理结果保存为文本文件 | ❌ 待实现 |
| CLI 参数 | 建议增加 `--output` / `-o` 参数指定输出路径 | ❌ 待实现 |

#### 3.2.7 目标检测推理（FUN-07）✅

- 支持 YOLOv4、YOLOv3、VGG-SSD、RT-DETR 四种目标检测模型
- 输入：图像文件（支持 jpg、png 等常见格式）
- 输出：检测框列表，每条包含类别 ID、类别标签、置信度、边界框坐标 (x1, y1, x2, y2)
- 对 YOLOv3/YOLOv4 输入使用 NV12 格式预处理，包含 DVPP 硬件缩放
- 后处理包含 NMS（非极大值抑制）过滤重叠框

#### 3.2.8 图像分类推理（FUN-08）✅

- 支持 ResNet50、MobileNetV1、VGG16 三种分类模型
- 输出：分类结果（类别 ID + 置信度）
- 各模型输入规格不同（见 2.3.1 节），系统自动按模型类型处理
- VGG16 模型支持 OOD 检测（见 3.2.10 节）

#### 3.2.9 语义分割推理（FUN-09）✅

- 支持 DeepLabV3+ 模型
- 输出：分割结果，包含图像宽/高、每个类别的像素数和占比、像素级分割图（seg_map）
- 分割图后处理使用 NEAREST（最近邻）插值 resize

#### 3.2.10 OOD 分布外检测（FUN-10）✅

- 针对 VGG16 cat/dog 二分类模型
- 通过置信度阈值 + Top 间隙（Top Gap）双重策略过滤分布外样本

#### 3.2.11 Python API 接口（FUN-11）✅

- 入口函数：`kzzk_cv(modelfile, imagefile)`
- 返回值：Python 字典
  ```python
  {
      "model_name": "yolov4",
      "model_type": "detection" | "classification" | "segmentation",
      "infer_cost": 25,
      "results": [...]
  }
  ```
- 实例缓存、日志过滤、自动资源释放

#### 3.2.12 C++ API 接口（FUN-12）✅

- 入口函数：`kzzk_cv::kzzk_cv(const std::string& modelfile, const std::string& imagefile)`
- 返回类型：`InferenceResult`（结构体）
- 文件预检查、静默模式、错误诊断

#### 3.2.13 C++ 共享库（FUN-13）✅

- 构建动态共享库 `libkzzk_cv.so`（版本 1.0.0，SOVERSION 1）
- 目标产物：`bin/kzzk_cv`（命令行工具）、`lib/libkzzk_cv.so.1`（共享库）、`bin/test_cv`（示例程序）

#### 3.2.14 一键安装部署（FUN-14）✅

执行 `cann/install_cann.sh` 依次完成权限/架构/驱动/CANN/编译工具/OpenCV 六项检查后编译安装。

#### 3.2.15 模型文件自动识别与分发（FUN-15）✅

根据 `.om` 文件名关键字自动匹配模型类型，支持 8 个模型关键字匹配规则（见 3.2.15 表）。

| 文件名包含关键字 | 匹配模型 | 模型类型 |
|---------------|---------|---------|
| `yolov4` | YOLOv4 | 目标检测 |
| `yolov3` | YOLOv3 | 目标检测 |
| `vgg_ssd` 或 `vgg-ssd` | VGG-SSD | 目标检测 |
| `rt_detr` / `rtdetr` / `rt-detr` | RT-DETR | 目标检测 |
| `resnet50` | ResNet50 | 图像分类 |
| `mobilenet` | MobileNetV1 | 图像分类 |
| `vgg16` | VGG16 | 图像分类 |
| `deeplabv3` / `deeplab` | DeepLabV3+ | 语义分割 |

#### 3.2.16 LLM 推理客户端（FUN-16）✅

| 需求编号 | 安全指标 | 要求 |
|---------|---------|------|

### 9.4 可维护性需求

| 需求编号 | 维护性指标 | 要求 |
|---------|-----------|------|
| MAI-01 | 日志过滤 | Python/C++ 默认屏蔽 CANN 原生 `[INFO]` 日志，便于调试时开启 |
| MAI-02 | 模型扩展 | 新增 CV 模型只需添加头/源文件并在工厂中注册关键字，无需修改调用层 |
| MAI-03 | PImpl 封装 | LLM C++ 客户端采用 PImpl 模式隐藏 libcurl 实现细节 |
| MAI-04 | RPATH 自包含 | 动态库与可执行文件内置 RPATH，运行时自动解析依赖 |

### 9.5 开发关键注意事项

| 注意事项 | 说明 |
|---------|------|
| NV12 字节序 | U 在前、V 在后（偶数字节 = U），**不是** NV21 |
| 输入类型 | 模型声明 uint8 就传 uint8，不要误传 float32（否则 size mismatch） |
| Device→Host 拷贝 | NPU 输出 buffer 在 Device 内存，必须 `aclrtMemcpy` 后才能 CPU 解析，否则段错误 |
| Softmax 时机 | 已含 Softmax 层的模型（如 VGG16），推理后不要重复做 Softmax |
| 分割图 resize | 必须使用 NEAREST 邻域插值，双线性会产生非法类别值 |
| VGG16 尺寸 | 224(宽) × 256(高)，非正方形，NV12 总字节 = 86,016 |
| 日志过滤顺序 | Python `stop()` 必须在 ACL 资源释放之后调用 |
